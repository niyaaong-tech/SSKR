# SSKR 로컬·클라우드 개발 컨텍스트

로컬을 주 작업 환경으로 유지하면서 클라우드에서 일부 개발을 진행하기 위한 실행·검증·인수인계 기준입니다. 제품 기획의 정본은 Notion이며, 이 문서는 현재 소스의 구조와 구현 계약을 설명합니다.

## 1. 작업 기준과 현재 상태

- 주 작업 경로: `C:\Project\SSKR\source`. 클라우드에서는 해당 저장소의 checkout 루트를 사용합니다.
- 운영 주소: https://sskr.vercel.app

로컬의 산출물 폴더, 브라우저 저장 상태, 미커밋 변경, 사용자 제공 원본은 클라우드 checkout에 자동 전달되지 않습니다. 로컬 파일 경로를 웹 URL이나 클라우드 실행 경로에 하드코딩하지 않습니다.

Notion에는 기획·정책·선정 기준과 미결정 사항만 기록합니다. 장소별 레코드·좌표·사진 메타데이터·대량 표·JSON은 공용 장소 소스와 로컬 `C:\Project\SSKR\exports`에서 관리하며 Notion에 업로드하지 않습니다. 인계용 `sskr-spots-catalog.json`에는 활성 `records`와 과거 참조용 `legacyRecords`를 분리합니다. 이 파일은 소스에서 생성하는 산출물이며 클라우드에서는 저장소의 공용 장소 소스를 기준으로 합니다.

## 2. 시작 절차

먼저 `AGENTS.md`와 이 문서를 읽고 작업 트리·브랜치·기준 커밋을 확인합니다. 클라우드 환경이 checkout을 준비했다면 다시 복제할 필요가 없습니다.

```sh
git status --short
git branch --show-current
git remote -v
git fetch origin
git rev-parse origin/main
```

깨끗한 checkout에서 요청 범위를 나타내는 기능 브랜치를 만듭니다. 아래 이름은 예시이며 기존 작업을 이어갈 때는 해당 브랜치를 사용합니다.

```sh
git switch -c feature/route-usability origin/main
npm ci
npx playwright install --with-deps chromium
```

브라우저의 OS 의존성 설치는 환경 권한이 필요할 수 있습니다. 권한이나 네트워크 제한으로 설치가 실패하면 임의로 검증을 통과 처리하지 말고 실패 원인과 가능한 검증 범위를 기록합니다.

수동 브라우징용 개발 서버:

```sh
SSKR_DEV_PORT=8080 npm run dev
```

Windows PowerShell에서는:

```powershell
$env:SSKR_DEV_PORT = '8095'
npm run dev
```

확인 주소:

- `http://127.0.0.1:8080/app/spots?scenario=guest`: 비로그인 탐색·루트 만들기
- `http://127.0.0.1:8080/app/spots?scenario=logged-in-no-application`: 로그인한 비참가자
- `http://127.0.0.1:8080/app/memorials?scenario=guest`: 공개 메모리얼
- `http://127.0.0.1:8080/explore/`: 공개 지도 탐색
- `http://127.0.0.1:8080/`, `/about/`, `/participate`: HOME·소개·참가 안내

실제 포트에 맞춰 URL을 바꿉니다. 개발 서버는 `127.0.0.1`에 바인딩합니다. 클라우드 미리보기 도구가 다른 바인딩을 요구하면 그 환경의 연결 방식을 먼저 확인합니다.

단순 정적 파일 서버로 대체하면 `/app/*` 라우팅, 지도 타일, 참가 API가 동작하지 않습니다. `server/dev-server.js`를 사용합니다. 브라우저 테스트는 각각 임시 포트의 서버를 자동 실행·종료하므로 사전에 수동 서버를 띄울 필요가 없습니다.

## 4. 유지해야 할 구현 계약

### 로그인 제공자와 실인증 전환

- 공용 `web/shared/auth/providers.js`가 새 로그인 제공자의 활성 상태를 관리합니다. Google만 활성화하고 네이버·카카오·Apple은 `준비 중`으로 비활성화합니다. 참가·APP 계정 화면·루트 저장 모달이 같은 정책과 컴포넌트를 사용합니다. 처리 중·실패 후에도 닫힌 제공자를 다시 활성화하지 않습니다.
- Mock 로그인 어댑터도 같은 정책을 확인하여 비활성 제공자의 새 연결을 거절합니다. 기존 Mock 세션·시나리오·계정 소유 기록은 보존합니다. Mock API의 요청 snapshot/account는 계속 테스트 전용이므로 이 제한을 실인증 보안으로 해석하지 않습니다.
- 백엔드 방향은 Supabase Auth·PostgreSQL·Storage와 기존 Vercel/Node API입니다. Google PKCE·서버 세션 검증부터 연결하고 실모드에서는 요청의 account/snapshot/scenario/mock.now를 신뢰하거나 Mock으로 대체하지 않습니다. 저장소·ActorContext·서버 Clock·트랜잭션 경계의 전환이 필요하며 이번 버튼 변경에 실제 OAuth 연결은 포함되지 않습니다.
- SSKR 전용 Supabase 프로젝트, 환경 분리·비용, Google OAuth 동의 화면·클라이언트·콜백 등록은 아직 연결 전입니다. SnapShare의 사용자·DB·비밀키를 재사용하지 않습니다. 구체적인 전환 순서와 개통 기준의 정본은 [Notion 데이터·서버 설계](https://app.notion.com/p/3cb4b875815381cfbfacda83552beeed)입니다.
- 인증 정책 수정 후 `npm test`, `npm run test:services`, `npm run test:routes`로 미개통 버튼 차단·실패 복구·게스트 초안 보존·Google Mock 저장을 확인합니다. 실제 OAuth 취소·만료·복귀·기기 간 저장 검증은 운영 연결 후 별도로 수행합니다.
- 이번 Google 우선 정책의 로컬 검증은 단위 181개·서비스 브라우저 23개·루트 브라우저 35개가 통과했습니다. 390px 모바일과 1440px PC의 로그인 화면을 확인했으며, 실제 Google OAuth와 iOS Safari 검증·운영 배포는 포함하지 않습니다.

### 매니저와 기록 화면

- 앱 메뉴는 매니저·스팟·메모리얼·내 기록 네 개입니다. 삭제된 행사 페이지 `/app/current`는 `/participate?view=guide`로 연결합니다. 안내 전용 진입은 로그인·신청 상태와 무관하게 공개 설명을 먼저 보여주며 기존 신청을 초기화하지 않습니다.
- 매니저의 참가 상태·다음 행동은 `event-view`와 공유합니다. 신규 결제는 확정 가능한 정원 확보 후에만 제공하며 결제 성공 후 참가를 확정합니다. 이전 WAITLIST_PAID 자료는 호환·운영 확인 대상으로 남기고 신규 유료 대기 흐름은 만들지 않습니다. 준비율·루트 개수·배송 예정일을 예시 값으로 채우지 않습니다. 저장 루트는 기존 계정별 루트 저장소에서 조회합니다.
- `/app/spots?mode=plan&tab=saved`는 기존 편집기와 저장 목록을 엽니다. 스팟 UI·추천·도로 계산 계약은 유지합니다.
- 메모리얼은 최신 공개일 순의 통합 갤러리이며 12개씩 추가합니다. 검색·행사·출발지 필터와 목록 복귀 위치를 보존합니다. 사진·방문 메모는 상세의 방문 순서별 목록에서 함께 표시합니다.
- `/app/memorials/all`은 `/app/memorials`, `/app/memorials/mine`은 `/app/my`로 연결합니다. 개별 기록·관리·공유 주소와 공개 범위 검사는 유지합니다.
- context 응답의 `pastParticipations`는 로그인한 계정의 지난 참가만 반환합니다. repository의 `getParticipationHistory()`가 조회 경계이며, 현재 mock 어댑터는 행사 fixture를 사용합니다. 메모리얼은 참여 ID로 연결하고 기록이 없는 참가도 유지합니다. 신규 운영 백엔드를 제공하는 변경은 아닙니다.
- `npm run test:services`로 안내·매니저·기록 흐름과 반응형 배치를 검증합니다. 합성 행사 표시 및 브라우저 한정 저장 안내를 제거하지 않습니다.

### 화면 전환·접근성·안내 배치

- 준비·계정 화면을 떠나면 해당 화면의 처리를 종료합니다. 늦게 도착한 저장 응답은 같은 계정·참가에만 반영하며, 현재 화면이나 다시 연 입력 폼을 덮어쓰지 않습니다. 준비 항목은 한 번에 하나만 저장하여 응답 간 상태 충돌을 막습니다.
- 상세 지도 초기화가 실패하면 부분 생성된 MapLibre 레이어·이벤트·컨테이너를 정리하고 공용 기본 지형과 장소 카드를 유지합니다. 정상 초기화 후 타일만 실패한 경우에는 기존 재시도·온라인 복구 흐름을 유지합니다. Leaflet 1.9.4의 확대 완료 콜백은 지도 인스턴스를 폐기한 뒤 실행하지 않도록 보호하며, 확대 중 화면 이동을 모션 기본·축소 설정 모두에서 검사합니다.
- 참가 안내의 가격·혜택·매니저 소개는 내용 높이에 맞춰 이어지고, 짧은 PC 화면에서도 서비스 패널을 스크롤해 끝까지 읽을 수 있어야 합니다. 로그인·신청 화면의 기존 구성을 유지합니다.
- APP 아이콘 메뉴의 접근성 이름은 글자 숨김 여부와 관계없이 유지합니다. About 본문 바로가기는 표시된 장면 제목으로 키보드 초점을 옮깁니다. HOME 메모리얼 장면은 본문·루트 선·사진 8장의 영역을 분리하고, 사진 위 메뉴의 대비를 확보합니다. 기존 모션 타이밍과 모션 축소 대안을 유지합니다.

### 참가 준비와 기록 편집

- `web/shared/event-rules.js`가 준비 항목·마감·일정 검토를 계산합니다. `web/app/preparation.js`의 바이크·공식 출발지·키트 수령 정보·안내 버전 확인은 기존 application API의 소유권·마감·발송 상태 검사를 통과해야 합니다. 개인 루트의 출발지와 공식 출발지는 별도 필드입니다.
- `web/shared/public-event.js`는 HOME·About 행사 표기를 공개 context의 실제 행사 값으로 갱신합니다. mock 세션을 공유하되 계정 상태를 별도 생성하지 않습니다.
- 메모리얼은 대표 사진·소개·방문 사진/메모 우선이며 지도는 접어둡니다. 소유자는 미발행·비공개 기록도 편집하고 발행 상태·방문별 사진 동의를 관리합니다.
- 추가 사진은 `web/app/memorial-media.js`의 IndexedDB 어댑터에 WebP로 저장합니다. 최대 15MB 입력·긴 변 1600px 제한·메타데이터 제거를 적용합니다. MOCK_UPLOAD 표시를 유지하며 실제 검수·업로드·동기화로 오인시키지 않습니다.
- 상단의 일정 입력은 저장 루트 필드가 아닌 계정·루트별 브라우저 키로 즉시 저장합니다. departureTime·breakMinutes와 autoDeparture를 보존하며 기존 빈 일정은 행사 일출 시각·120분으로 읽습니다. 공식 출발지 불일치·일몰 마감 검토는 안내이며 저장 권한을 바꾸지 않습니다.
- 저장 후 실행 취소는 방문 순서·제목 등 편집 내용만 되돌립니다. 저장 ID·소유권·생성 시각은 유지하며 일반 재저장은 같은 기록을 갱신합니다. 새 기록은 새 루트·명시적 복제에서만 만듭니다. 루트와 일정 저장 중 일부만 성공하면 그 상태를 구분해 안내합니다.
- 방문별 로컬 사진 선택은 재적용해도 중복되지 않습니다. 삭제한 `local-photo-*`의 `MOCK_UPLOAD`는 미리보기에서 제거하되 원본 장소 사진·운영 업로드는 보존합니다. 내 기록·갤러리·상세는 같은 `coverVisitId`와 소유자 공개 권한으로 대표 사진을 선택합니다.
- 공개 메모리얼의 URL 필터는 실제 행사·출발지 선택지로 정규화합니다. 존재하지 않는 ID는 전체로 복구하되 유효한 검색 조건은 유지합니다. APP 라우터는 일반 내부 왼쪽 클릭만 처리하고 Ctrl/Meta 등 보조 키, 새 창, 다운로드, 외부 링크는 브라우저 기본 동작을 유지합니다.

### 장소와 지도

- 지도 패널의 크기 변경은 Leaflet과 MapLibre를 함께 동기화합니다. 세션 복원·모바일/PC 전환에서 어댑터 외곽만 바뀌고 GL 캔버스가 이전 탐색 높이에 남으면 배경과 마커가 어긋납니다. Leaflet resize와 기존 ResizeObserver 이후 다음 프레임에 어댑터 getSize 기준 외곽 크기·위치와 MapLibre.resize()를 함께 반영합니다. 카메라 구도를 바꾸는 우회 방식은 사용하지 않습니다. 회귀 검증은 속초·내륙·남해·제주 좌표의 두 지도 투영 오차 2px 미만을 확인합니다.
- 남한 기본 지형은 공용 `land.geojson`을 Leaflet SVG로 상세 지도 아래에 항상 유지합니다. MapLibre 배경은 투명해야 합니다. Leaflet과 MapLibre의 줌 값은 1단계 차이가 있어, 상세 타일의 최소 줌 전에도 육지가 사라지지 않아야 합니다. 타일 지연·실패 시에도 지형·마커·루트 조작은 유지하고, 네트워크 재연결 시 실패한 타일을 다시 요청합니다.

- 현재 카탈로그는 **경유 200곳 + 출발 11곳 + 도착 1곳**입니다. 도착지는 `daecheon`(대천해수욕장)입니다. HOME의 지도 연출과 마지막 기록 카드도 같은 도착지를 표시합니다. 개수와 장소 ID는 테스트로 확인합니다.
- `web/explore/places.js`의 42개 기반 데이터만 보고 전체 목록으로 오인하지 않습니다. curation을 적용한 `SSKR_SPOT_CATALOG`가 활성 목록입니다.
- 장소 ID는 저장 경로와 메모리얼의 참조입니다. 삭제된 ID를 임의의 새 장소로 자동 치환하지 않습니다. 활성 목록에서 제외된 장소의 기존 기록은 legacy 참조로 유지합니다.
- 권역 UI와 `corridor`는 제거됐습니다. 다시 도입하지 않습니다. 지역·장소 유형·카테고리·검색은 유지합니다.
- 지도 안내 좌표 `lat/lng`는 확인된 주차 지점입니다. 확인된 관광 장소 좌표는 `visitCoordinate`로 따로 관리합니다. 출발·도착을 포함해 주차 좌표 간 직선거리 5km 이하 쌍이 없어야 합니다. 가까운 장소는 대표 명소를 우선 남깁니다. 경기 남부에 10개 경유 스팟을 두며 서울과 경기 북부는 제외합니다. 방문 장소와 주차 지점의 거리는 1km 이내, 주차 지점과 검증된 이륜차 도로의 스냅 거리는 750m 이내로 구분합니다.
- 도로 생성은 `tools/build-route-data.py`와 `tools/route-requirements.txt`를 사용합니다. 저장소 밖 `--work`에서 `prepare → graph → routes` 순서로 실행합니다. `routes --catalog <카탈로그 JSON> --output <검증용 도로 폴더>`로 활성 소스를 바꾸기 전에 계산하고, 장소 ID·순서·버전과 전체 구간을 확인한 뒤 카탈로그·사진·도로를 함께 적용합니다. 카탈로그 JSON은 장소 배열 또는 exports의 `records`를 받을 수 있습니다.
- 도로 검증은 `edge_walk`를 우선 사용합니다. 해당 매칭이 실패한 경우에만 공식 `walk_or_snap`으로 재검증하며, 원본의 모든 구간이 같은 좌표값·순서로 확인돼야 합니다. 검증 응답의 연속 중복점이나 부분 순환 도로를 통째로 반환한 추가 루프만 처리하고, 좌표 이동·근처 도로 치환은 거절합니다. 끝점 반올림 때문에 정방향 일치 확인이 실패하면 정확한 역방향 좌표로 도로 속성만 조회합니다. 이 속성 조회에서만 방향 제약을 해제하며 실제 경로 계산은 일방통행을 준수합니다. 어느 방식이든 모든 OSM way ID를 이륜차 허용 목록과 대조하며 공개 데이터에는 최초 계산한 최단 경로만 저장합니다. 실패가 기록된 캐시 행은 재생성하고, 정상 행은 같은 버전일 때 재사용합니다. `python -B -m unittest discover -s tests/routes -p test_policy.py`로 필터·매칭 정책을 검사합니다.
- 이륜차 접근, 주차, 짧은 방문 동선을 확인한 장소와 출처·재사용 조건이 확인된 실제 사진을 사용합니다. 이미지 경로·크레딧을 함께 관리하고 웹 이미지는 WebP를 사용합니다.
- 지도·사진 카드·레이아웃은 스팟·메모리얼·공개 탐색이 공유합니다. 북한 육지, 남쪽 해안선, 제주·울릉·독도의 표시를 보존합니다. 상세 정보 제거와 육지 제거를 혼동하지 않습니다.
- 기존 줌·이동 제한, 모바일 하단 4열의 아래 행부터 채우는 배열, 최대 12개 카드, 접히는 지도 출처 표시를 유지합니다.
- **호버는 사진만 표시**하고 지도를 이동하지 않습니다. **선택한 카드에만 추가 버튼**을 표시하며 실제 카드·버튼 크기와 패널·제어 영역을 고려해 화면 안으로 이동합니다.
- 마커와 번호는 선명하게 유지합니다. 선택·추천·경로 포함 상태는 색과 테두리로 구분하며 불투명도를 낮추지 않습니다. 숫자 원은 24px과 중심 앵커를 함께 사용하고, 한·두·세 자리 숫자와 사진 배지의 중심 정렬을 모바일·PC에서 확인합니다.
- `SSKR_MAP.formatPlaceText`는 표시용 중점을 공백으로 바꿉니다. 이름과 지역을 한 줄에 함께 표시할 때만 사이에 ` · `를 둡니다. 표시 정리를 이유로 저장 데이터를 일괄 변경하지 않습니다.
- 스팟 탐색 URL은 선택한 장소 ID와 `spotSearch`, `spotKind`, `spotCategory`를 함께 보존합니다. 기본 스팟·모든 카테고리는 매개변수를 생략하며, 잘못된 필터 값은 기본값으로 처리합니다. 새로고침·링크 공유 후에도 같은 검색 조건을 복원합니다.
- 루트 편집에서 탐색으로 돌아올 때 지도 모드를 먼저 전환한 다음 기존 탐색 필터에 맞춰 화면을 맞춥니다. 지도 안에 결과가 없으면 `전체 장소 보기`로 현재 검색 결과를 다시 볼 수 있습니다.

### 완주 체크인

- Event의 `minimumSpotCheckins`는 기본 10, 1 이상의 정수입니다. 출발·고정 도착은 별도로 필수이며 경유 수에 포함하지 않습니다. 기본 완주 개수 조건은 경유 10 + 양 끝 2 = 총 12곳 이상입니다. 해당 과거 Event 설정을 보존합니다.
- `web/shared/checkin-rules.js`는 유효한 출발부터 도착까지의 서로 다른 검증된 경유 스팟을 집계합니다. 합성 Event에서만 SIMULATED 체크인을 허용합니다. GPS·시간·자격을 포함한 운영 완주 판정기는 별도 준비 범위입니다.
- API context·루트 완성 표시·자동 완성은 같은 행사 최소값을 읽습니다. 저장 형식은 유지하며 부족한 루트도 초안 저장할 수 있습니다. 메모리얼 더미 30개는 10·11·12곳의 경유 체크인과 실제 도로 형상으로 생성합니다.

### 루트 편집

- 실제 터치 검증은 기존 route-planner 브라우저 harness의 hasTouch/isMobile + locator.tap을 사용한다. 기본 엔진은 기존 Edge/Chromium이며 BROWSER_ENGINE=webkit으로 WebKit을 선택할 수 있다. WebKit은 기존 Playwright CLI의 install webkit으로 준비한다. Windows WebKit 터치 에뮬레이션은 실제 iPhone Safari 검증을 대신하지 않는다.
- 지도 번호는 탐색·편집·사진 카드와 내 경로의 행에서 같은 상태 체계를 사용한다. 미추가 스팟은 밝은 둥근 사각형, 묶음은 옅은 녹색의 둥근 사각형이며 n스팟으로 표시한다. 800px 이하에서는 묶음 표시를 높이 18px·글자 9px·좌우 여백 3px과 내용에 맞는 폭으로 줄인다. 실제 클릭 영역 48×30px과 중심 앵커는 유지하며 801px 이상은 기존 표시 크기를 유지한다. 내 경로는 채운 녹색 원형과 방문 순서 번호를 쓰고, 핀고정은 같은 원형에 올리브색·따뜻한 테두리·작은 핀 표식을 더한다. 출발·도착은 역할 색상을 유지하며 경로 포함 여부에 따라 같은 사각형/원형 규칙을 따른다. 선택은 형태·바탕색을 바꾸지 않고 금색 외곽선으로 표시한다. 추천 후보도 미추가 형태를 유지한다. 핀 아이콘은 장식이며 지도 마커 선택이 핀 상태를 변경하지 않는다.
- 사용자에게 스팟은 출발지·경유 장소·도착지 전체를 뜻한다. 경유 장소만 뜻할 때는 경유 스팟으로 설명하며 화면 동작은 스팟 추가·스팟 자동 완성·스팟 재구성으로 표기한다. 최소 N은 출발·도착을 제외한 경유 스팟 수이며 저장 필드·공개 API·도로 데이터는 바꾸지 않는다.
- 스팟 탐색·루트 출발지 선택의 기본 배율과 축소 한계는 남한 본토 중심으로 맞춘다. 속초부터 남해안까지 가용 화면 높이를 채우며, 제주·울릉·독도는 지도 이동으로 볼 수 있다. 모바일 탐색에서는 하단 사진 목록을, 모바일 편집에서는 지도 하단 요약을 피해 본토를 배치한다. 확대 후에는 기존 지도 이동 제한으로 돌아간다. 5~8레벨 국내 타일을 번들 캐시해 기본 타일은 외부 공급망 조회 없이 제공한다. 섬과 북한 지형은 삭제하지 않는다. 장소 URL이나 명시적 선택이 없는 첫 진입에서는 사진 카드를 자동 선택하지 않아 지도 구도가 이동하지 않는다. 작성된 루트 전체 보기와 개별 검색·선택의 위치 이동은 별도로 유지한다.
- 출발지 미선택 행은 출발 마커와 통일한 골드 계열의 출발지 선택 버튼을 사용한다. 장소 아이콘·단일 문구·화살표로 구성하고 다음 도착지 행과 16px 간격을 둔다. 보조 문구는 표시하지 않는다. 화살표의 짧은 CSS 움직임은 두 차례 뒤에 멈추며 움직임 줄이기 설정에서는 정지한다. 출발지 선택은 사진 격자 dialog를 사용한다. 삽화 도움말과 함께 넓은 dialog·내부 세로 스크롤·고정 닫기 영역을 제공한다. 삽화는 `web/app/assets/route-help/`의 공용 SVG 네 장으로 관리한다.
- 장소 찾기 패널은 제목 → 카테고리 탭(모두/카페/맛집/자연/역사) → 검색 → 결과 순서이다. 추천 목록 제목은 추천 스팟으로 표시하며 카테고리 탭은 같은 폭과 가로·세로 중앙 정렬을 사용한다. 좁으면 탭만 가로 스크롤하며 키보드 방향키로도 이동한다. 펼침형 필터와 추천 카드의 출발/도착 구간 문구는 제거한다. 구간명은 원본 장소 필드가 아니므로 추가하지 않으며, 방향별 도로 계산용 ID와 거리·시간 증감은 유지한다.

- PC는 **내 경로 → 지도 → 장소 찾기**의 3영역이다. 상단은 루트 이름·저장 상태·관리·거리와 예상 주행 시간·출발 시각·휴게시간·기능 버튼을 배치한다. 넓으면 한 줄, 부족하면 두 줄로 늘리며 헤더 ResizeObserver가 실제 높이를 지도 배치에 반영한다. 좌우 폭에 상한을 두며 지도에 남은 폭을 배정한다. 브라우저 폭 800px 이하에서는 전체 페이지 스크롤과 지도·두 목록 탭 sticky로 전환한다. 내 경로 → 장소 찾기 순서이며 편집 진입·새로고침·새 루트·불러오기의 기본 탭은 내 경로다. 출발지 선택 후에는 장소 찾기로 이어지고 사용자가 선택한 탭과 상세 왕복 흐름은 유지한다. 모바일 도구는 이름·관리·실행 취소·저장을 첫 줄, 출발 시각·휴게시간을 둘째 줄에 두며 키보드 순서도 일치시킨다. 도움말은 활성 목록 하단으로 옮겨 360px에서도 이름 입력 폭 140px 이상을 확보한다. 변경 상태는 접근성 상태로 유지하며 첫 줄 높이를 늘리지 않는다. 일정은 16px 라벨 행과 44px 입력 행으로 정렬하고 두 필드 사이 12px 간격을 유지한다. 시간 입력의 native appearance·내부 padding·최소/최대 block 크기를 명시하되 type=time과 기본 피커는 유지한다. 44px 터치 영역과 16px 입력 글자를 유지하고 스팟 수·부족 안내·초기화를 같은 요약 영역에 모아 중복 제목과 여백을 줄인다. 패널 펼치기·접기·드래그와 목록 내부 스크롤은 없다.
- 장소 찾기는 추천과 검색을 합친다. 검색어가 없으면 추천, 입력하면 검색 결과이며 카테고리는 항상 적용한다. 상세 왕복 후 검색·필터·읽기 위치를 보존한다. 편집 세션에는 탐색 진입 전 필터도 보존하며 새로고침 후 탐색으로 돌아갈 때 복원한다. 저장 목록은 제목 옆 폴더의 루트 관리 dialog에서 제공한다. 루트 이름은 상단 입력창에서 직접 수정하며 한 번의 입력을 한 단계로 실행 취소한다. 최대 60자이고 빈 이름은 저장할 때 계정의 기존 번호와 겹치지 않는 루트 01 형식으로 자동 부여한다. 관리 창의 현재 루트 요약과 이름 변경 팝업은 제거했다. 저장 항목은 이름 → n 스팟 경유와 부족 수 → 출발·도착 → 거리·시간 → 불러오기·복제·삭제 순서로 배치한다. 부족 수는 현재 Event 최소값을 기준으로 빨간색 스팟 n개 부족으로 표시하며 최소 수 충족·초안 배지를 중복 표시하지 않는다. 기존 tab=saved 주소와 openSaved 호출은 이 창을 연다.
- 출발지 선택 전에는 출발지만 선택한다. 선택 후에도 모든 출발지 마커를 검색·카테고리 필터와 별개로 유지하며 개별 선택할 수 있게 표시한다. 현재 출발지는 경로 포함 상태로 구분하고 다른 출발지의 선택 카드에는 출발지 변경 버튼을 표시한다. 현재 출발지 사진 카드의 설정 완료 배너는 표시하지 않는다. 호버에는 버튼을 표시하지 않는다. 출발지 변경은 확인 팝업 없이 즉시 적용하며 경유 스팟·핀고정·상대 방문 순서·저장 ID를 유지하고 실행 취소로 이전 출발지를 복원한다. 선택 후 추천·스팟 추가·자동 완성을 활성화한다. 게스트 편집과 도로 조회, 로그인 비참가자의 저장, 최소값 미만 초안 저장을 유지한다.
- UI의 직접 구간 선택기는 제거했다. bestInsertion과 insertionRecommendations는 모든 방향별 인접 도로의 A→후보→B − A→B를 비교한다. 거리 증가량·시간 증가량·앞쪽 구간 순으로 선택하며 기존 장소 순서를 유지한다. 후보 상세·기존 경유 스팟 선택은 추가 방식에 영향을 주지 않는다. 출발지만 있으면 전체 동선의 약 1/N 지점을 추천한다.
- 선택된 지도 사진 카드에만 추가 버튼을 둔다. 추가 가능한 카드의 버튼 아래에는 삽입 구간 번호·거리 안내를 표시하지 않는다. 호버·추천 목록·상세에는 추가 버튼을 복원하지 않는다. 추가 직전 경로를 재확인하고 두 도로를 읽은 뒤 적용한다. 중복·도로 실패·오래된 요청은 원본을 변경하지 않는다.
- 자동 완성·스팟 재구성·경로 최적화는 미리보기 없이 바로 적용한다. 최소 경유 수(Event N, 기본 10) 미만이면 자동 완성 하나, N곳 이상이면 스팟 재구성과 경로 최적화 두 버튼을 내 경로 하단에 나란히 표시한다. 더보기 메뉴 자체를 제거하고 일정은 상단 입력으로 제공한다. generation은 전용 AbortController와 revision/context/경로/일정/Event signature를 갖는다. 처리 중 원본 지도·목록을 유지하고 진행 표시만 바꾼다. 편집·일정 변경·취소·전환·화면 이탈로 무효가 된 결과는 저장·알림·취소 기록을 변경하지 않는다.
- UI의 자동 완성과 재구성은 같은 rebuild 계산을 사용한다. pinnedStopIds에 있는 경유 스팟만 상대 순서대로 유지하고 고정하지 않은 기존 경유 스팟을 제외한 후보로 N곳까지 채운 뒤 순서도 최적화한다. 핀고정 수가 N보다 많으면 모두 유지한다. autoFill의 기존 호출 규약은 유지하며 rebuild에서 제외 후보를 전달한다. 방향별 도로를 검증한다. UI는 입력된 주행 시간 예산으로 우선 계산하고 최소 경유 수를 채우지 못하면 예산 제한 없이 연결 가능한 완전한 조합을 다시 계산한다. 일정 초과는 실제 ETA와 도착 지연 경고로 표시하며 경로 구성 자체를 차단하지 않는다. domain.autoFill/rebuild의 명시적 drivingBudgetSeconds 호출 규약은 유지한다. 도로 실패나 충분한 새 후보가 없는 경우에만 원본을 유지하고 새 조합 생성 실패를 안내한다. 기존 경로 개수가 부족하다는 문구는 사용하지 않는다. 핀 변경·초기화도 진행 중 계산을 무효화한다.
- 경로 최적화는 양 끝·장소 집합·핀고정한 장소의 상대 순서를 유지하고 실제 도로 거리가 줄어든 경우에만 한 번 적용한다. 기존 경로 자체가 일정 예산을 넘으면 개선도 금지되던 제한을 적용하지 않으며 변경된 실제 ETA 경고는 유지한다. 개선 없음·실패에는 빈 실행 취소 기록을 추가하지 않는다.
- 공통 실행 취소는 최대 30개의 편집 snapshot을 관리하며 새 루트·불러오기도 되돌린다. 입력 영역 밖에서 Ctrl/Cmd+Z를 제공한다. 같은 context의 편집은 최신 저장 ID를 유지하고 context 전환 취소는 이전 ID·소유권·내용과 일정을 복원한다. 별도 복구본·복구 메뉴와 전환 확인창은 없다. 현재 세션의 새로고침 복원은 유지한다.
- 제목이 있는 루트는 그 이름으로 저장하고 없는 루트는 계정별 빈 번호를 찾아 루트 01 형식으로 저장한다. 루트 1과 루트 01은 같은 번호로 예약하며 삭제·이름 변경으로 비워진 번호는 재사용한다. 명시적 복제만 새 ID를 만들고 일반 재저장은 같은 ID를 갱신한다. 루트·일정 저장 일부 실패는 구분해 표시한다.
- 내 경로 행은 번호·이름·드래그 핸들과 오른쪽 위 삭제 X·바로 아래 핀고정 아이콘으로 구성한다. 출발·고정 도착에는 핀고정·삭제 아이콘을 두지 않는다. 장소명을 누르면 지도에서 해당 장소를 확인하고, 순서는 핸들 드래그 또는 키보드 위아래 방향키로 변경한다. 삭제 X와 핀 아이콘은 작게 표시하며 PC 32px·모바일 44px 조작 영역을 확보하고, 출발지·고정 도착지에는 표시하지 않는다. 모바일 조작 버튼은 목록과 함께 스크롤한다. 자동 완성 진행 문구는 버튼에만 표시하며 오류·재시도 안내는 하단에 유지한다.
- 스팟 초기화는 내 경로 제목 옆에 둔다. 핀고정이 없으면 취소 / 초기화, 있으면 취소 / 핀고정 제외 / 전부 초기화 선택을 제공한다. 핀고정 제외는 고정한 장소만 남긴다. 양 끝·저장 ID는 보존하며 초기화와 핀 변경도 실행 취소·새로고침 복원 대상이다. 저장 버전 1에 선택 필드 pinnedStopIds를 추가하고 기존 루트의 기본값은 빈 배열로 읽는다. 삭제된 경유 스팟의 핀은 normalize에서 함께 제거한다.
- 일정 기본값은 event-rules.scheduleDefaults가 solar-times.windowFor의 검증된 Event 일출과 행사 출발 시작 시각 중 늦은 시각을 분 단위로 올림하고 행사 시간대로 변환해 계산하며 휴게시간은 120분이다. 기존 운영 데이터가 없으면 CALCULATED_MOCK에서만 계산 예시를 쓰고 STALE/UNAVAILABLE 값은 임의 보완하지 않는다. 출발 시각을 직접 수정하면 autoDeparture=false로 보존하고, 자동 기본값인 경우에만 출발지·행사 설정에 맞춰 갱신한다. 시간·분 입력과 ±15분 버튼은 필드를 다시 생성하지 않고 일정 안내·기능 상태만 즉시 갱신한다. 유효하지 않은 일정에서는 자동 기능을 잠그며 장소 선택·초안 저장은 유지한다.
- 최소 체크인·예상 시간의 한계·긴 안내는 도움말에 모으고 상시 일정 미검토 카드는 두지 않는다. 도착 예상은 n 스팟 경유 뒤에 오전/오후 형식으로 표시한다. 부족 수와 실제 일정 경고만 별도 줄로 표시하고 긍정적인 마감 여유시간은 생략한다. 이른 출발은 출발 시각을 HH:mm 이후로 조정해 주세요로 안내하며 실제 도착 지연·공식 출발지 불일치 경고는 보존한다. 지도 카드·출발지 갤러리·공개 탐색 전달의 출발지 변경은 같은 즉시 적용 흐름을 사용한다.
- 경유 스팟 드래그는 대상 행의 위·아래 절반으로 삽입 구간을 정한다. 단일 드롭 슬롯을 실제 행 사이에 삽입해 간격을 넓히고 여기에 놓기를 표시한다. 출발·도착은 고정하고 취소·동일 위치 드롭은 내용과 실행 취소 기록을 바꾸지 않는다.
- createStore의 maxSavedRoutes 기본값은 10이다. 계정별 전체 초안·완성 루트를 집계하며 새 ID만 상한을 검사한다. 기존 ID의 재저장은 허용하고 오래된 초과 데이터는 삭제하지 않는다. 이름과 개수는 로그인 계정의 저장 목록으로 결정하며 공개 저장 형식은 버전 1을 유지한다. ROUTE_LIMIT_REACHED 실패에는 편집 상태를 유지하고 안내를 지속한다. 운영 서버의 원자적 개수·번호 처리는 관리자 설정 예정 문서에 기록한 별도 구현 범위다.
- 선택 해제는 마커·사진 카드·경로 행의 시각적 강조를 함께 정리하고 session.selectedId와 anchorId를 null로 보존한다. 뒤늦게 완료된 경유 스팟 도로 조회도 해제한 선택을 되살리거나 새 상세 선택을 빼앗지 않는다. 자동 완성·재구성·최적화의 시작, 지도 빈 곳·전체 경로 보기, 장소 선택 컨트롤 외 지도 밖 클릭에 적용한다. 장소 선택 버튼·드래그 핸들·대화상자는 동작을 유지하고 상세 읽기 내용과 위치는 보존한다. 사진 호버는 실제 마우스 pointerenter/leave에서만 별도 Tooltip으로 열고 닫으며 선택 해제와 별개로 사진만 노출한다. 미선택 마커에는 Leaflet 자동 mouseover/click 툴팁을 연결하지 않는다. 터치의 합성 마우스 이벤트가 DOM을 먼저 바꿔 iOS의 후속 클릭을 소모하지 않도록 하고 한 번의 탭에서 선택·사진·동작 버튼을 표시한다. 선택된 마커만 영구 Tooltip을 연결한다. 지도 DOM에는 position:absolute와 inset:0을 생성 시 명시해 Leaflet 초기화 시 relative 위치로 바뀌며 높이가 0px이 되는 WebKit 경로를 방지한다. 마커 재생성·화면 해제 시 호버 Tooltip과 포인터 리스너를 정리하며 터치 시작·종료를 강제로 가로채지 않아 지도 드래그와 핀치 기본 동작을 유지한다.
- 경로 포함 마커 선택은 PC의 내 경로 스크롤 컨테이너에서 해당 행을 가시 영역에 노출한다. 모바일에서는 내 경로 탭으로 연결하고 sticky 지도·탭 아래에 행을 놓는다. 사진 카드의 상세 열기는 계속 제공한다. viewer.setRoute의 선택 메타데이터 pinnedIds는 현재 경로의 핀만 받아 올리브색 번호와 접근성 이름으로 표시하며 저장 형식은 바꾸지 않는다.
- 루트 만들기에서는 지도 상단의 장소 집계를 숨긴다. 스팟 탐색의 지도 안 필터와 집계 상태는 모드 전환 때 복원한다.
- 전체 경로 보기에는 네 모서리 맞춤 아이콘을 사용하며 패널의 중복 맞춤 버튼은 없다. 짧은 지도에서도 선택 카드·추가 버튼과 제어·요약 영역을 함께 계산한다. 모바일 키보드 표시에는 지도 sticky를 해제하고 탭만 유지한다. 화면 전환 시 지도 인스턴스를 재사용한다.

### 일출·일몰과 관리자 연결 경계

- `web/shared/solar-times.js`는 행사 현지 날짜·출발지·피니시 좌표로 개발용 일출·일몰을 계산합니다. NOAA 공개 계산식을 사용하며 KST 오프셋을 한 번만 적용합니다. 출발은 분 단위 올림, 도착 마감은 내림을 사용합니다. `CALCULATED_MOCK`, 출처와 `noaa-fractional-year-1` 버전을 유지하며 공식 역서·현장 검증값으로 표시하지 않습니다. 출처: https://gml.noaa.gov/grad/solcalc/solareqns.PDF
- 봄·가을 QA 예시는 `2027-04-17`, `2027-10-16`입니다. 실제 행사 확정일이 아닙니다. 강릉 출발/대천 피니시의 계산 예시는 각각 05:48/19:08, 06:32/17:57 KST이며 좌표와 계산식에 따라 KASI 예시와 소폭 다릅니다. 공식 운영 전 행사 장소와 [한국천문연구원 자료](https://astro.kasi.re.kr/kor/life/pageView/9)를 재확인합니다. 현재 공개 행사 목업 날짜를 이 예시로 임의 교체하지 않았습니다.
- context는 `sunlightMode`, `sunlight`, `configVersion`을 전달합니다. 검토 데이터 `sunlight`는 `eventId`, 현지 `date`, `timezone`, `configVersion`, `verification: REVIEWED`, `sourceUrl`, `calculationVersion`, `starts`, `finish`를 갖습니다. 각 장소는 `locationId`, `lat`, `lng`, `sunriseAt` 또는 `sunsetAt`를 갖습니다. 날짜·좌표·설정 버전이 불일치하면 오래된 값으로 분류해 일정 확인을 요청합니다. 관리자 검토 없이 운영 데이터가 `REVIEWED`로 승격되어서는 안 됩니다.
- 일정은 운영 출발 가능 시각과 선택 출발지 일출 중 늦은 시각, 운영 도착 마감과 피니시 일몰 중 이른 시각을 사용합니다. 휴식·관광 시간을 포함한 ETA와 경유 개수 충족은 별개입니다. 천문 자료가 없는 일반 이벤트는 운영 시각만 검토하고 일출·일몰 미확인을 표시합니다. 시간·도로 정보는 실시간 교통이나 안전·완주를 보장하지 않습니다.
- 관리자 화면·권한·행사 등록/수정 메뉴는 별도 후속 구현입니다. 참가자용 매니저를 관리자 기능으로 해석하지 않습니다. 후속 흐름은 행사 날짜·장소 변경 → 위치별 시각 재계산 → 관리자 검토·공개 → 안내·일정·자동 완성 갱신입니다. 역할 체계, 변경자/시각/이전값 보존, 계산 실패, 기존 저장 루트 재검토 정책을 먼저 확정합니다. 이번 변경은 운영 인증·DB·관리자 UI 개발을 포함하지 않습니다.

### 데이터와 백엔드 경계

- 현재 로그인·신청·결제는 mock입니다. 메모리얼 행사와 GPS 시각은 합성 테스트 데이터입니다. 화면이 동작한다는 이유로 실운영 인증·결제·DB가 구현됐다고 판단하지 않습니다.
- 루트 저장은 `route-plan.js`의 계정별 localStorage 어댑터, 편집 복원은 `sessionStorage['sskr.route-editor']`입니다. 과거 편집 세션의 insertion 값은 읽지 않으며 저장 루트·공개 API 형식은 유지합니다. 브라우저·origin·포트가 달라지면 작성 상태와 저장 목록이 공유되지 않습니다. 기기 간 동기화는 아직 없습니다.
- 루트 필드 `id/title/startId/stopIds/finishId/catalogVersion/routingVersion/createdAt/updatedAt`와 소유자 식별, 공개 API 형식을 보존합니다. 도로 형상을 저장 루트마다 복제하지 않습니다.
- 백엔드 연결은 저장·인증·도로 조회 어댑터 경계에서 진행합니다. 권한을 화면 숨김에만 의존하지 않습니다.
- 도로 데이터는 거리 최단 기준으로 생성하며 고속도로·자동차전용도로·명시적 이륜차 금지·사유지·페리·비포장·보행 전용 도로와 조건부 제한을 제외합니다. 내비게이션 기능으로 확장하지 않습니다.
- 장소 ID·주차 좌표·도로 정책이 바뀌면 manifest·거리 행렬·압축 형상·접근 좌표를 함께 재생성·검증합니다. UI 작업만 할 때는 기존 도로 데이터를 재생성하지 않습니다.

## 5. 검증과 네트워크

기본 검증:

```sh
npm test
npm run test:routes
npm run test:maps
npm run test:spots
git diff --check
```

변경한 JavaScript에는 `node --check <파일>`을 실행합니다. HOME·About·공개 탐색을 수정했다면 해당 테스트도 직접 실행합니다.

```sh
node --test tests/browser/home.test.js
node --test tests/about.test.js
node --test tests/explore.test.js
```

- 루트·지도 브라우저 테스트는 Windows에서 Edge, Linux에서 설치한 Chromium을 사용합니다. `BROWSER_CHANNEL`이 설정돼 있으면 그 채널이 우선합니다. Linux에서 Edge 채널을 그대로 지정하지 않습니다.
- 브라우저 테스트의 일부는 UI용 모의 도로 응답을 사용합니다. 테스트를 위해 만든 직선 연결을 운영 provider로 옮기지 않습니다. `npm test`의 실제 생성 도로 검증과 실제 도로 브라우저 사례를 함께 확인합니다.
- 모바일 360·390·430px, 짧은 화면·가로 화면, 768px, PC 1280·1440·1920px을 확인합니다. 후보 확인→자동 삽입→순서 이동·삭제→실행 취소→자동 완성·루트 최적화→새 루트·불러오기·전환 취소→저장을 연속 조작합니다.
- hover·클릭·키보드 선택을 구분하고, 지도 이동·확대와 모바일 페이지 스크롤 또는 PC 패널 스크롤이 충돌하지 않는지 확인합니다. 모바일의 긴 목록·상단 헤더 소멸·sticky 위치·검색 키보드와 화면 회전도 확인합니다.
- 실제 iPhone의 키보드·터치와 실운영 로그인은 에뮬레이션·mock 검증과 구분해 보고합니다.
- 설치에는 npm 레지스트리와 Playwright 브라우저 다운로드 접근이 필요합니다. 지도 실행에는 `unpkg.com`, `tiles.openfreemap.org` 접근이 필요합니다. upstream 타일 호스트는 `/planet` 응답으로 정해집니다.
- `HTTP_PROXY`·`HTTPS_PROXY`가 설정된 클라우드에서는 Node.js 24의 서버 측 타일 조회에도 프록시를 적용해야 합니다. 개발 서버와 브라우저 테스트를 실행하는 셸에 `NODE_USE_ENV_PROXY=1`을 설정합니다(예: `NODE_USE_ENV_PROXY=1 npm run test:maps`). 기존 프록시와 CA 신뢰 설정을 유지하며 운영 타일 조회 코드를 우회 응답으로 바꾸지 않습니다.
- 낮은 줌 타일 캐시는 Git에 포함되어 있지만 브라우저 라이브러리·glyph·sprite와 높은 줌 타일은 외부 네트워크에 의존합니다. 네트워크가 막힌 환경에서는 지도·사진 시각 검증 범위를 정확히 보고하며 기능 코드로 실패를 숨기지 않습니다.
- QA 출력이 필요하면 `SSKR_QA_OUTPUT`을 저장소 밖 임시 경로로 지정합니다. 캡처·로그·다운로드·브라우저 캐시는 커밋하지 않습니다.

도로 생성 도구를 바꾼 경우에만 별도 Python 가상환경에 `tools/route-requirements.txt`를 설치하고 다음 검증을 추가합니다.

```sh
python -B -m unittest discover -s tests/routes -p "test_*.py"
```

전체 재생성의 prepare→graph→routes 명령과 원본 OSM 주소는 README의 「스팟 주행 루트 편집」을 따릅니다. 원본 PBF·그래프는 저장소 밖에 둡니다. 지도 경계가 바뀐 경우에는 `npm run map:cache`도 필요합니다. 작업 환경에서 생성하지 못하면 일부 자산만 게시하지 말고 필요한 로컬 생성 작업을 인계합니다.

## 6. 로컬·클라우드 병행 규칙

1. **로컬이 통합 책임을 가집니다.** 클라우드는 요청한 기능만 별도 브랜치에서 개발하고 결과 커밋·PR을 인계합니다. 별도 지시 없이 main merge·운영 배포를 진행하지 않습니다.
2. 클라우드 시작 시 최신 원격 main의 SHA를 기록합니다. 로컬의 미커밋 변경은 볼 수 없다는 전제로 작업 범위를 나눕니다.
3. 공유 지도·카탈로그·루트 핵심 파일을 양쪽에서 동시에 바꾸는 경우에는 담당 범위를 먼저 구분합니다. 기존 합의가 명확하면 불필요한 승인 요청 없이 그 범위에서 진행합니다.
4. 작업 도중 main이 변경되면 합치기 전에 차이를 검토합니다. 무조건 pull·force push·hard reset·자동 stash로 현재 작업을 덮지 않습니다.
5. 로컬에서 결과를 통합할 때 먼저 작업 트리를 확인하고 브랜치의 변경을 검토합니다.

```sh
git status --short
git fetch origin
git log --oneline main..origin/feature/route-usability
git diff main...origin/feature/route-usability
```

로컬 미커밋 작업을 보존한 상태에서 통합 방법을 정합니다. 깨끗한 호환 작업 트리라면 fast-forward를 우선하고, 분기됐다면 필요한 merge·충돌 해결 후 실제 합쳐진 코드로 다시 검증합니다. 파일 전체를 한쪽 버전으로 대체하지 않습니다.

클라우드 완료 보고에는 다음을 포함합니다.

- 시작 main SHA, 결과 브랜치·커밋 또는 PR
- 수정 파일과 사용자에게 달라지는 동작
- 실행한 테스트의 통과·실패·미실행과 사유
- 지도·데이터·사진 재생성 여부
- 로컬에서 이어서 해야 할 검증·통합 작업

인수인계용 문서나 상태 정보를 날짜별로 복제하지 않습니다. 지속적으로 필요한 기술 기준은 이 문서를 수정하고 작업 결과는 커밋·PR로 남깁니다.

## 7. 배포와 자산 주의사항

- 운영은 main의 Git 연동 배포를 사용합니다. `vercel --prod`로 같은 변경을 다시 배포하거나 `.vercel` 연결 파일을 새로 만들지 않습니다.
- 명시적인 배포 요청이 있을 때 main 반영→push→Vercel READY→운영 alias→커밋 SHA 일치→영향 경로와 변경 자산 확인 순서로 검증합니다. push 성공만으로 배포 완료라고 보고하지 않습니다.
- Vercel 프로젝트: `prj_IJuMBUZ5yC1M041vUaIIHunTaPtz`, 팀: `team_Voiu5udniLzdbBRgaj9BPRA4`. 식별자이며 비밀값이 아닙니다. 배포 권한은 연결 계정에서 별도로 확보합니다.
- 기본 UI 개발에는 운영 비밀값이 필요하지 않습니다. 토큰·쿠키·개인정보·.env 값을 코드·문서·로그로 복사하지 않습니다.
- 현재 도로 행 161개는 약 64.5MiB입니다. 모두 배포에 사용하는 자산입니다. 압축 파일이라는 이유로 지우거나 QA 캐시와 혼동하지 않습니다.
- 최근 추가된 장소 WebP 92장(약 12.7MiB)은 공용 런타임 자산입니다. 출처와 크레딧을 유지합니다.
